A common skepticism about online technical internships is: *"There is no evidence of real technical work."* For generic certificate mills, that criticism is completely fair. When applied to DBERT's active engineering tracks, however, it misses the actual architecture fellows are required to ship.

Rather than assigning static CRUD to-do lists, DBERT sprint tickets map directly to production engineering disciplines used by Indian AI startups and SaaS teams.

## Active Project Tracks & Actual Engineering Skills

| Project Track | Actual Engineering Skills & Stack | Typical Sprint Deliverable |
|---|---|---|
| **Hybrid RAG Engineering** | Vector search (`pgvector`, Qdrant), BM25 + dense retrieval pipelines, chunking, cross-encoder reranking | Low-latency retrieval API with precision/recall evaluation harness |
| **SaaS Feature Development** | Multi-tenant architecture, tenant-scoped PostgreSQL schemas, REST & streaming APIs | Role-scoped SaaS endpoint with idempotent billing/usage webhooks |
| **Authentication & Web Security** | JWT rotation, OAuth2 PKCE flows, OWASP Top 10 hardening, rate limiting | Hardened auth middleware with CSRF/XSS/injection test coverage |
| **QA Automation** | PyTest fixtures, Postman contract collections, Playwright E2E browser suites | CI-integrated regression suite blocking broken PR merges |
| **Document Processing** | OCR pipelines, Tesseract, OpenCV preprocessing, Python structured parsing | Automated PDF/invoice extraction pipeline with JSON schema validation |
| **Bot Development** | Telegram, WhatsApp, and Discord APIs, webhook verification, state machines | Production notification & command bot with retry/circuit-breaker logic |

## Deep Dive: What Senior Mentors Review in Your PRs

During Weeks 3–6 of the [DBERT Fellowship](/learners/fellowship), code is not graded on whether it "runs once on your laptop." Mentors review pull requests against production criteria:

```
  [ Candidate PR ]
         │
         ├──▶ 1. Architecture & Isolation (Tenant boundaries, clean module boundaries)
         ├──▶ 2. Security & Auth (JWT expiry, OAuth2 scopes, OWASP input sanitization)
         ├──▶ 3. Reliability & Tests (PyTest / Playwright / Postman assertions pass)
         └──▶ 4. Originality & Docs (Turnitin < 3% + clear README & API contracts)
         │
         ▼
  [ Merged to Active Repo + Rubric Score Logged on /verify ]
```

### 1. Hybrid RAG & Retrieval Pipelines
Fellows move beyond basic `similarity_search()` calls. Sprints require combining sparse keyword matching (BM25) with dense embeddings, tuning chunk overlap, and logging retrieval latency and faithfulness metrics. Learn the exact patterns in our [How-To Guide on Hybrid RAG & Multi-Tenant SaaS](/blog/how-to-build-hybrid-rag-and-multi-tenant-saas-in-internship).

### 2. Multi-Tenant SaaS & Security Hardening
Multi-tenancy is where junior codebases break most often. Fellows implement strict `tenant_id` query scoping, short-lived JWTs with refresh rotation, OAuth2 callback validation, and OWASP Top 10 protections (SQLi, SSRF, broken object-level authorization).

### 3. QA Automation, OCR & Bot Integrations
Engineering teams rely heavily on automation engineers who can validate releases and process unstructured data. Fellows build Playwright E2E flows, PyTest + Postman API contract tests, Python + Tesseract OCR pipelines, and resilient webhook bots for WhatsApp, Telegram, and Discord. Read the step-by-step patterns in our [QA, OCR & Bot Automation Guide](/blog/how-to-automate-qa-ocr-and-bots-production-guide).
