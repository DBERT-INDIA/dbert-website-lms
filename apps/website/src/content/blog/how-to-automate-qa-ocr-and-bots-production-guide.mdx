## 1. How to Structure a 3-Layer QA Automation Suite

Relying only on manual click-testing guarantees regressions before every release. A production QA sprint combines three layers:

1. **API Contract & Schema Tests (Postman / Newman + PyTest):** Verify HTTP status codes, JSON schema types, and idempotency keys on every pull request.
2. **Service & Integration Tests (`pytest`):** Use isolated test fixtures to validate business logic, error handling, and database constraints.
3. **Browser E2E & Mobile Viewport Checks (Playwright):** Assert critical user journeys (login, form submission, mobile `scrollWidth <= innerWidth` checks) across Chromium and mobile viewports.

```python
# Example PyTest + Playwright viewport overflow check
def test_mobile_no_horizontal_overflow(page):
    page.set_viewport_size({"width": 390, "height": 844})
    page.goto("https://dbert.in/enroll/1999")
    overflow = page.evaluate("document.documentElement.scrollWidth > window.innerWidth")
    assert overflow is False
```

## 2. How to Build a Reliable Python + Tesseract OCR Pipeline

Passing a raw phone photo of an invoice or certificate straight into `pytesseract.image_to_string()` produces garbled output. Production document processing requires a **preprocessing stage**:

1. **Normalize DPI & Grayscale:** Rescale low-resolution scans to ~300 DPI and convert to grayscale with OpenCV.
2. **Denoise & Adaptive Threshold:** Remove uneven lighting shadows using `cv2.adaptiveThreshold`.
3. **Deskew & Crop:** Detect text angle and rotate before OCR.
4. **Structured Extraction:** Parse the extracted text with regex + Pydantic validation so downstream systems receive clean JSON (e.g., UTR numbers, dates, totals) instead of raw text blobs.

## 3. How to Architect Production Bot APIs (Telegram, WhatsApp, Discord)

Whether you are building an internal DevOps alert bot on Discord, a candidate support bot on Telegram, or an automated notification workflow via WhatsApp APIs, toy scripts fail under real traffic.

Production bot architecture requires:
- **Webhook Signature Verification:** Validate `X-Hub-Signature-256` (WhatsApp) or Ed25519 headers (Discord) before processing payloads.
- **Persistent Deduplication & State:** Store message IDs and conversation states in PostgreSQL or SQLite WAL mode so webhook retries never double-send messages.
- **Rate-Limit Pacing & Circuit Breakers:** Enforce randomized human-safe delays or token-bucket queues, and trip a circuit breaker after consecutive upstream failures.
